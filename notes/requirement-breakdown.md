# 需求拆解练习：病历结构化助手

## 1. 页面

- 用户看到什么：标题、病历输入框、分析按钮、结果区
- 用户输入什么：一段病历文本
- 用户点击什么：分析按钮
- 结果怎么显示：症状、诊断、用药三个区域
- 出错怎么显示：页面顶部或结果区显示明确错误提示

## 2. 接口

- 地址和方法：`POST /api/analyze`
- 请求字段：`text`（病历文本）；Prompt 放在后端，不由前端传入
- 响应字段：`symptoms`、`diagnosis`、`medications`

## 3. 数据库

- 是否需要持久化：需要，用于查看历史分析记录
- 存哪些字段：`id`、`text`、`result_json`、`created_at`

## 4. AI 调用

- 什么时候调用：用户点击“分析”后
- 输入什么：病历文本 + 后端 Prompt
- 输出什么格式：JSON，包含 `symptoms`、`diagnosis`、`medications`
- 校验和错误处理：后端校验 JSON 和必需字段；格式错误则重试或返回清晰错误

## 5. 业务流程

1. 用户输入病历文本
2. 用户点击“分析”按钮
3. 前端发送 `POST /api/analyze`
4. 后端调用大模型
5. 后端校验 JSON 和必需字段
6. 后端保存分析结果到数据库
7. 后端返回结果，前端显示
